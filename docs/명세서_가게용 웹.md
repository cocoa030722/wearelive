# WEARELIVE 기능명세서 — 가게용 웹 v0.1

> 기준일 2026-10-01 · 버전 v0.1 (초안)  
> 대상: 가게(호스트·사장님)가 PC·노트북 브라우저로 쓰는 **웹 페이지**(React, D-27). 모바일 앱이 아니다.  
> 짝 문서: `명세서_사용자용 모바일 앱.md`(이하 '사용자 명세서') · `개발가이드.md` · `가게용웹_미결정목록.md`(이하 '미결정목록') · 시안 `사장님앱 v1.0.0.html`(이하 '사장님 시안')

**이 문서가 하는 일** — 가게용 웹의 기능을 화면 단위로 정의한다. 사용자 명세서 WL-HOST-01(가게용 웹)을 요구 ID WL-HOST-02~로 나누고, 각 항목에 화면 구성·흐름·규칙·데이터·미정을 적는다. 사장님 시안은 **모바일 앱 형태로 그려졌지만 이 문서는 웹으로 옮겨 적는다**(하단 탭 바 → 좌측 메뉴, 길게 누르기 → 클릭·드래그, 스플래시 → 로그인 직후 상태 확인). 시안이 기존 결정과 다르면 결정을 따르고, 시안에만 있고 사용자 명세서에 없는 기능은 1차 범위에서 뺀다(CLAUDE.md 절대 규칙 1).

## 표기 원칙

- `[시안 O-xx]` = 사장님 시안의 해당 화면에서 확인한 사실. 더미 값(밴드명·가격·시간·수치)은 데이터 예시이며 정책이 아니다(하드코딩 금지).
- `[결정 D-xx]` / `[결정 Qn]` / `[결정 2026-09-30]` = 사용자 명세서 13장·부록 D의 결정.
- `[결정 미결정 n-n]` = 미결정목록 '결정' 열에 적힌, 시안이 아닌 직접 결정(예: 1-2 비밀번호 규칙). 아직 부록 D에 옮기지 않았다.
- `[명세서 우선]` = 시안과 기존 문서가 달라서 기존 문서 값을 쓴 곳(괄호 안은 근거).
- `[명세서 밖]` = 시안에만 있는 기능이라 1차에서 뺀 것. 넣으려면 H-36 결정이 필요하다.
- `[추정]` = 문서에 없지만 흐름상 필요해서 가정한 것. 그대로 구현하고 작업 보고에 적는다.
- `[미정 H-xx]` = 정하지 않은 것. 구현하지 말고 `// TODO(H-xx)`를 남긴다. 결정 요청은 12장.
- 돈·권한·예약 상태는 **서버(Spring Boot)에서만** 정한다. 웹은 서버가 준 값을 보여주고 요청을 보낼 뿐이다. 이 문서에 나오는 금액·남은 시간·권한 판정은 모두 API 응답값이다.

## 3 · 계정 · 입점

### WL-HOST-02 로그인

**화면:** 사장님 시안 O-01 (웹 페이지로 변환)

**화면 구성**

- WEARELIVE PARTNER 로고 · 인사 문구 [시안 O-01]
- 이메일 · 비밀번호 입력 · '자동 로그인' 체크 · [로그인] · '비밀번호 찾기' 링크 [시안 O-01 · 명세서 우선]
- '아직 입점하지 않으셨나요?' + [입점 신청] [시안 O-01]

**흐름**

- [로그인] → 성공하면 2.2절 게이트대로 이동 · 실패하면 입력란 아래 오류 문구 [추정]
- '비밀번호 찾기' → WL-HOST-05 · [입점 신청] → WL-HOST-03

**규칙·정책**

- 로그인 = 이메일 + 비밀번호. 사용자 앱(카카오·구글)과 별개 계정 [결정 2026-09-30]
- 시안의 휴대폰 번호 로그인, 소셜 로그인(카카오·네이버·Apple)은 쓰지 않음 [명세서 우선 — 부록 D 2026-09-30]
- 인증 = 서버 발급 토큰 [시안 O-00 · 개발가이드 4.2]. 자동 로그인을 체크하면 브라우저를 닫아도 로그인 유지. 유지 기간 → [미정 H-03]
- 직원 계정도 같은 화면에서 로그인(WL-HOST-07)
- 로그인 실패 횟수 제한 → [미정 H-03]

**데이터**

- `host_account(email, password_hash)` — 11.1절

### WL-HOST-03 입점 신청 (계정 만들기)

가게가 직접 가입한다. 입점 신청이 유일한 가입 경로다 [결정 미결정 1-1 · 시안 O-01·O-02].

**화면:** 사장님 시안 O-02

**화면 구성**

1. 계정: 이메일 → [인증 코드 보내기] → 코드 입력 · 비밀번호 · 비밀번호 확인 [결정 미결정 1-2, 시안에 없음 → 추가]
2. 사업자 정보: 사업자등록번호 · 상호 · 대표자명 · 연락처(휴대폰) [시안 O-02] + 사업장 주소 · 사업자 이메일 [명세서 우선 — D-25]
3. 사업자등록증: '사진 촬영 또는 파일 선택' → 웹에서는 파일 선택(이미지·PDF) [시안 O-02 → 웹 변환 추정]
4. 약관: '약관 전체 동의' + 이용약관(필수) · 정산약관(필수) · 개인정보 수집·이용(필수) · 마케팅 정보 수신(선택), 항목마다 '보기' [시안 O-02]
5. [심사 신청하기] · 안내 '제출 후 영업일 기준 1–2일 내 결과를 알려드립니다' [시안 O-02]

**흐름**

- [심사 신청하기] → 계정 생성 + 신청 저장 → WL-HOST-04(심사 중)

**규칙·정책**

- 비밀번호: 8자 이상, 특수문자 1개 이상, 영문 대문자·소문자 각 1개 이상 포함 [결정 미결정 1-2]. 검증은 서버가 하고 웹은 입력 중 안내만 보여줌
- 이메일 인증: 이메일로 보낸 코드를 입력 [결정 미결정 1-2]. 코드 자릿수·유효 시간 → [추정] 6자리, 10분
- 같은 이메일 중복 가입 불가 [추정]
- 필수 약관 3개에 동의하고 필수 입력을 모두 채워야 [심사 신청하기] 활성화 [추정]
- 시안의 **정산 계좌(은행·계좌번호·예금주) 입력은 뺀다** — 계좌를 시스템에 두지 않음 [명세서 우선 — 부록 D 2026-09-30 정산 방식]
- 연락처(휴대폰) = 새 요청 알림톡 수신 번호(`host.phone`). 로그인 ID 아님 [결정 2026-09-30]. 휴대폰 인증 여부 → [미정 H-33]
- 사업자 정보는 **가게 단위로 한 번** 입력하고, 그 가게의 모든 공간 상세에 같은 값을 표시 [결정 미결정 2-9]
- 사업자등록증 파일: 저장 위치 = S3 비공개 버킷, 조회는 서버가 발급한 서명 URL로 운영자만 [추정 — 개발가이드 4.2 이미지 저장 S3]. 용량·형식 → [미정 H-05]
- 약관 본문 → [미정 H-06](법무)
- 동의 기록(항목·동의 시각) 저장 [추정 — 사용자 앱 Q4와 같은 원칙]

**데이터**

- `host`(상호·대표·등록번호·주소·전화·이메일·심사 상태) · `host_account`(owner) · `host_terms_agreement` · 사업자등록증 파일 키 — 11.1절

### WL-HOST-04 심사 대기 / 반려

### 11.1 개발가이드 1장 대비 추가·변경 (모두 [추정] — 첫 작업 전에 확정)

```sql
-- 로그인 주체를 host에서 분리 (직원 계정 여러 개, 미결정 1-4)
create type host_role as enum ('owner','staff');
create type host_review_status as enum ('pending','rejected','approved');

create table host_account (
  id uuid primary key, host_id uuid not null references host,
  email text not null unique, password_hash text not null,
  email_verified_at timestamptz,
  name text not null, role host_role not null,
  perm_reservation boolean not null default true,   -- 예약 승인 (시안 O-50)
  perm_settlement  boolean not null default false,  -- 정산 조회 (시안 O-50)
  created_at timestamptz not null default now(), deleted_at timestamptz
);
create unique index host_one_owner_uidx on host_account (host_id) where role = 'owner' and deleted_at is null;

create table host_invite (id uuid primary key, host_id uuid not null references host, token text not null unique,
  perms jsonb not null, expires_at timestamptz not null, used_at timestamptz, created_by uuid references host_account);

-- host: email·password_hash는 host_account로 이동. 심사 상태·사업자 정보(가게 단위, 미결정 2-9) 추가
alter table host
  add column review_status host_review_status not null default 'pending',
  add column review_reject_reason text,
  add column business_doc_key text,          -- 사업자등록증 S3 키 (비공개)
  add column business_name text, add column business_owner text, add column business_reg_no text,
  add column business_address text, add column business_phone text, add column business_email text;
-- venue.business_* 6개 컬럼은 삭제하고 공간 상세에서 host 값을 쓴다

create table host_terms_agreement (host_id uuid references host, term_code text, agreed_at timestamptz not null,
  revoked_at timestamptz, primary key (host_id, term_code));

-- 시간 차단 (미결정 3-2, 시안 O-14)
create table venue_block (
  id uuid primary key, venue_id uuid not null references venue, room_id uuid not null references room,
  start_at timestamptz not null, end_at timestamptz not null,    -- 단일 차단 또는 반복 전개 결과 1건
  series_id uuid,                                                -- 반복 차단 묶음 (같은 등록에서 나온 행)
  memo text, created_by uuid references host_account,
  created_at timestamptz not null default now(), deleted_at timestamptz,
  check (end_at > start_at)
);
-- 반복은 등록 시 종료일까지 행으로 전개해 저장 (가용성 계산을 단순하게). 종료일 규칙은 H-38

-- 거절 사유 (미결정 4-1)
alter table reservation add column reject_note text;            -- 가게가 고른·입력한 사유. conflict면 null

-- 예약 상태 변경 이력 (시안 O-12)
create table reservation_event (
  id uuid primary key, reservation_id uuid not null references reservation,
  kind text not null,              -- requested / payment_authorized / host_notified / confirmed / rejected / expired / cancelled / completed / refund_*
  actor_type text not null,        -- user / host_account / system / admin
  actor_id uuid, note text, created_at timestamptz not null default now()
);

-- 가게 쪽 미읽음 (시안 O-40) — 사용자 앱 읽음 표시와 무관 (Q55)
alter table conversation add column host_last_read_at timestamptz;

-- 알림톡 발송 기록 (미결정 8-5)
create table host_notification_log (id uuid primary key, host_id uuid not null references host,
  reservation_id uuid references reservation, channel text not null default 'alimtalk', template text not null,
  status text not null, attempts smallint not null default 0, sent_at timestamptz, created_at timestamptz not null default now());

-- 이메일 인증 코드 · 비밀번호 재설정 토큰
create table host_auth_token (id uuid primary key, email text not null, purpose text not null,  -- verify_email / reset_password / invite
  token_hash text not null, expires_at timestamptz not null, used_at timestamptz);
```

### 11.3 검증 시나리오 추가 (개발가이드 2.8에 덧붙일 후보)

23. 직원 계정(예약 승인만)이 정산 API를 부르면 거부된다.
24. A 가게 계정이 B 가게 예약을 조회·확정하면 거부된다.
25. 심사 중·반려 계정은 공간·예약 API를 쓸 수 없다.
26. 차단된 시간은 사용자 앱 가용성에서 빠지고, API로 요청해도 거부된다.
27. 확정 예약과 겹치는 차단 등록은 겹치는 구간을 빼고 저장되며 뺀 구간이 응답에 온다.
28. 거절 사유 없이 거절하면 거부되고, 사유를 넣어 거절하면 채팅 거절 카드에 사유가 남는다.
