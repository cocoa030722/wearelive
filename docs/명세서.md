# WEARELIVE 기능명세서 v2.1

> 신 Figma 시안(WL) 기준 · 확인 문답 결정 반영 · 화면 이미지 61장 포함  
> 기준일 2026-09-28 · 버전 v2.1 (결정 반영판)  
> 디자인 정본: Figma 파일 WL (figma.com/design/KNjSBM9a9OCpcaOkf0KZuI) · 페이지 '프로토타입' · 프레임 128 + 컴포넌트 6

**이 문서가 하는 일** — 신 Figma 시안이 그린 WEARELIVE 앱의 기능을 화면 단위로 정의한다. 회원가입·밴드·소식·예약·결제/환불·채팅·내정보를 요구 ID(WL-xxx-nn)로 나누고, 각 항목에 화면 이미지·화면 구성·사용자 흐름·규칙·데이터·미정 사항을 적는다. 시안에 없는 것은 '없음/미정'으로 명시하며 임의로 채우지 않는다. v2.1은 2026-09-27~28 확인 문답의 결정을 반영했다. 본문에서 결정된 [미정]은 [결정 D-xx]로 바꾸고, 13장 표에 결정 결과를 채우고, 결정으로 새로 생기거나 달라진 요구는 14장에, 전체 결정 목록은 부록 D에 둔다.

## 표기 원칙

- [F] = Figma 프레임에서 확인한 사실. 프레임의 텍스트·레이어를 그대로 옮긴다. 더미 값(가격·날짜·이름·후기)은 시안 값을 인용한 것이며 확정 정책이 아니다.
- [추정] = 프레임에 직접 표시되지 않았지만 흐름상 자연스러운 가정. 구현 전 확인 대상.
- [미정] = 시안·기존 문서 어디에도 정의가 없는 항목. 13장 '결정 요청'에 모아 둔다.
- 요구 ID는 WL-<영역>-<번호>. 영역: AUTH(가입·온보딩) BAND(밴드) NOTICE(공지) SCHED(일정) PHOTO(사진) MEMBER(멤버) NEWS(소식) VENUE(대관 탐색·상세) BOOK(예약) PAY(결제·환불) CHAT(채팅) MY(내정보) NOTI(알림) SYS(공통).
- 기존 통합 기능명세서 v1.3(2026-06-10)의 ID(AUTH-01 …)는 '구 ID'로만 참조한다. 변경 이력은 별도 문서 'WEARELIVE 앱 변경 기획서 v1.0'에 있다.
- [결정 D-xx] = 확인 문답에서 정한 사항. 시안([F])과 다르면 결정이 우선한다(예: 시안의 수수료 10% → 결정 5%). 근거와 전체 목록은 부록 D.
- v2.1에서 요구 ID 영역 HOST(가게용 웹)를 추가했다.

## 1 · 핵심 기능 요약

요청받은 형식(기능 – 세부 항목)으로 WL의 핵심 기능을 먼저 한 장에 정리하고, 이어서 기능 맵(대분류 → 기능 → 화면 → 요구 ID)을 둔다. 세부 정의는 3~10장.

## 2 · 정보 구조 · 내비게이션 · 화면 목록

## 14 · 결정으로 추가·변경된 요구 (v2.1)

확인 문답에서 새로 생기거나 시안과 달라진 요구. 시안 프레임이 없어 이미지 없이 정의한다. 요구 ID는 기존 영역 번호를 이어서 쓰고, 가게용 웹은 새 영역 HOST로 둔다.

### WL-BAND-04 밴드 삭제 (대표 제안 → 멤버 투표)

대표가 밴드 삭제를 제안하면 멤버 투표로 결정한다(게임의 항복 투표 방식). 되돌릴 수 없어 기준을 높게 둔다. [결정 D-10]

**화면:** 시안 없음 (결정으로 추가된 요구)

**사용자 흐름**

- 대표: 멤버 관리(⚙) 또는 밴드 설정 → '밴드 삭제 제안' → 확인 → 투표 시작, 멤버에게 푸시 [추정]
- 멤버: 밴드 프로필 상단 투표 카드에서 찬성/반대 [추정]
- 3일 안에 전체 멤버의 2/3 이상 찬성 → 삭제 · 미달 → 부결

**규칙·정책**

- 통과 기준 = 전체 멤버 수의 2/3 이상 찬성(투표하지 않은 멤버는 찬성으로 세지 않음)
- 투표 기간 3일, 기간 안에 기준을 못 넘으면 부결
- 결과 표시 = 인원 수(찬성 N · 반대 N)
- 1인 밴드는 대표 혼자 찬성으로 통과
- 진행 중인 삭제·종료 투표는 밴드당 1건 [추정]

**데이터**

- BAND_VOTE(id, band_id, type ∈ {delete, archive}, proposed_by, starts_at, ends_at, status ∈ {open, passed, rejected}) · BAND_VOTE_BALLOT(vote_id, user_id, choice, voted_at)

**예외·미정**

- 삭제 후 공지·사진 데이터 보존 기간
- 투표 카드·제안 화면 시안 필요

### WL-BAND-05 밴드 활동 종료 (아카이빙)

- 밴드 전환 목록에 '활동 종료' 표시

- 활동 종료 상태에서 멤버 탈퇴·초대 가능 여부

### WL-BOOK-07 예약 상세 · 사용자 취소

**사용자 흐름**

- 가게 3% 수수료의 부분 환불 처리 [추정: 환불 후 실제 정산액 기준]

### WL-BOOK-09 대기 요청 규칙 (시간대 선점 없음)

요청형 공간은 확정 전까지 시간대를 잡아두지 않는다. 가게는 여러 요청 중 고를 수 있다. [결정]

**화면:** 시안 없음 (결정으로 추가된 요구)

**규칙·정책**

- 같은 룸·시간대의 대기 요청은 최대 3건, 3건이 차면 그 시간은 요청 불가
- 일시 선택·상세에 '이 시간 요청 N건 대기 중' 표시
- 가게가 하나를 확정하면 겹치는 나머지 요청은 자동 거절 + 승인 취소(전액)
- 만료 = 결제 완료 + 24시간, 이용 시작이 더 빠르면 시작 전(버퍼 미정) [결정 D-33]
- 검색의 '예약 가능' 판정: 확정된 예약과 대기 3건이 찬 시간만 제외 [추정]

**데이터**

- 요청 생성 시 같은 룸·시간대 requested 수 확인(≤ 3) · 확정 트랜잭션에서 겹치는 요청 일괄 거절

### WL-PAY-07 수수료 · 가격 표시

가게 3% + 사용자 5%로 나눠 받는다. 가격은 처음부터 사용자 수수료를 포함해 보여준다. [결정 D-34]

**화면:** 시안 없음 (결정으로 추가된 요구)

**규칙·정책**

- 예) 합주실 ₩15,000 × 4시간: 사용자 결제 ₩63,000 · 가게 정산 ₩58,200 · 플랫폼 ₩4,800 (PG 수수료·부가세 차감 전)
- 예) 공연장 ₩100,000 × 4시간(가정 가격): 사용자 ₩420,000 · 가게 ₩388,000 · 플랫폼 ₩32,000
- 상한 없음
- 리스트·결과·상세의 시간당 가격 = 수수료 포함 금액(예: ₩15,000 → ₩15,750/시간), 예약 확인에서 요금·수수료를 나눠 표시 [추정 표기]
- 취소 시 사용자 수수료도 요금과 같은 비율로 환불(D-32)

**예외·미정**
